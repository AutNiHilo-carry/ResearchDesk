# 整句事实前提候选 v3：两批各两轮对照

2026-11-23，针对[已讲解混合句开发回归](factuality-mixed-regression.md)增加显式候选report-quote-v3，并完成8次真实评分。**本轮v2与v3标签完全相同，未证明v3更好，不晋升默认策略。** 原报告、原成绩和人工待审表不改，独立人工审核仍pending。

## 具体实现

ModelJudge显式支持prompt_version="v3"；quality的verify／benchmark可用`--judge-prompt v3`。v3在原v2后追加逐分句检查指令：只要任一子句仍含可核查的行为或事实前提，整行就保留为事实；是否已被证明与是否提出断言分开；无引用的断言仍进入事实分母。纯建议或纯未知声明仍可非事实，不使用生产关键词分类器。

不输出中间推理或新的原子断言字段，不改JSON schema、单条摘录独立支持整行的合同、引用指标或门槛。v1/v2字节合同未修改；v2提示hash仍是`d2556557c2871b028b22f80e359cdaac84c045e6e929292cd70f5658eecfbbfd`。业务评测、修订与工作流没有切到v3；quality CLI默认v1亦不变。v3当前仅支持line验证；clause组合在加载凭证前拒绝。

显式启用的独立开发评分示例（会付费，一次批量请求）：

```powershell
.\.venv\Scripts\python.exe -m researchdesk.quality benchmark --dataset evals/factuality-mixed-dev-v1.json --judge-prompt v3
```

这里的benchmark通过只表示与Agent候选参考符合，不是独立人工准确率。本轮实际实验另行使用既有run_stability API和事前冻结计划，没有通过此命令反复调参到通过。

## 事前条件

两批payload：6条固定开发案例，以及原Stripe API v1报告的8个完整逐行单元。后者从源正文／Ledger重建，并与上一轮四组实验保存的quote-only payload逐项比较一致；没有只摘出容易判断的一句话。参考标签和解释曝光标识不进入模型请求。

每批v2先2次，再v3两次；固定顺序，每轮同一payload，deepseek-flash、temperature=0、timeout=90、max_tokens=8192、max_retries=0及JSON输出设置相同，无来源上下文增量。模型别名不等于后端快照固定。未随机化，重复数小；原报告和开发例子已用于发现问题，不算独立held-out集。

冻结原报告全部文件hash、数据集／旧输入计划／编排脚本／代码hash、提示和输入hash、每组2轮及总上限8次SDK请求。一次性execution目录阻止重跑；失败也消耗预定轮次，不补轮。仅发送公开资料摘录与报告行到配置的DeepSeek接口；无生成或搜索，Tavily0。8次不是金额／Token上限，金额未测。

## 实际观察

8轮均通过结构校验，标签在同一批次内跨轮／跨提示完全相同；下面是事实性和引用标签，不表示独立人工正确性。

| 批次 | v2两轮 | v3两轮 | v2返回Token | v3返回Token |
| --- | --- | --- | --- | --- |
| 6条开发例子 | 各6/6事实判断符合候选参考 | 各6/6符合候选参考 | 2559 | 3087 |
| 原Stripe 8单元 | 各6个事实、精度2/3、覆盖2/6 | 各6个事实、精度2/3、覆盖2/6 | 3706 | 4149 |
| 合计 | 4次请求 | 4次请求 | 6265 | 7236 |

实际8次请求、13501返回Token，v3比v2多971 Token，未观察到标签收益。单次小样本不能推断普遍成本比例。没有追加请求来寻找更有利的一轮。

原混合句U7在本轮两提示各两轮均被判factual=true；原四组实验却有3次排除该行。这说明本轮原v2也能给出预期判断，不能将与历史的变化归因于v3。保留历史标签，不用新标签回填旧成绩。

更完整地计入未引用事实，会增加分母。原报告本轮覆盖2/6=0.3333，历史原稿覆盖2/5=0.40，正文并未变化；不能把这个下降当作生成报告退步，也不能仅把分母缩小后的高分当作改进。

## 只读审阅兼容性修复

新增候选提示会改变源码hash。原context_reference把所有历史源码hash都与当前安装版本比较，即使旧输入／提示／模型标签完全一致，也会阻止只读审阅。这与付费执行的代码冻结需求不同。

现在历史代码hash保留、校验格式并进入原包绑定；只读入口重建所有原输入／提示并重放单元、引用和派生指标，不要求安装源码逐字相同。旧付费计划仍严格检查代码版本，在升级后拒绝执行。没有修改旧plan中的hash，也没有对付费入口放宽校验。

真实旧审阅包已重新核验，packet与原包逐项相同，实验和包文件hash未变；旧付费执行在加载凭证前被拒绝。新回归分别验证“代码升级但输入合同不变可只读审阅”和“付费旧计划仍拒绝”，以及历史hash格式错误拒绝。材料漂移、提示变化、缓存指标篡改和模型结果字节绑定检查继续保留。
