# 技术选型报告的人工复核入口

2026-11-17，本轮复用已有 `researchdesk.review`，导出原技术选型两组报告的待填包，没有新增模型评分，也没有填写人工标签。

## 入口修复

原评测入口有两种合法资料保存方式：全部任务集资料，或仅所选任务用到的资料。报告策略对照采用后者。旧人工复核入口却要求结果中的 corpus 与整个任务集完全相同，因此拒绝了实际3题对照结果。

现在要求：所选任务必需资料全部存在；已记录资料不能超出任务集；每份记录哈希与任务集一致；每份冻结快照内容也一致。编号按评测记录中 corpus 的插入顺序还原，匹配原 `evaluate_batch` 的写盘顺序。完整任务集资料仍被支持，不跳过任何已记录快照。任务集整体哈希、任务身份、报告证据完整性和导入绑定检查继续保留。

## 已生成的待填材料

两个目录均留在忽略的 runs 中，不随公开仓库发布：

- `runs/reviews/technical-selection-v1-20261117/`
- `runs/reviews/technical-selection-v2-20261117/`

每组3份完成报告，来自原计划 `7f88e78851ba4fe39cab347c1780d93a`。v1 原评分失败，v2 原模型判定1/3通过；这些模型判分不显示在复核阅读材料中。目录名仍能区分写作策略，不能称为随机盲审。

文件含义：

| 文件 | 用途 |
| --- | --- |
| reading.md | 阅读原问题、全部标准、正文、逐行编号、证据摘录和来源全文 |
| packet.json | 结构化材料与绑定哈希；不包含模型判断标签 |
| review.json | 空白人工填写表，事实/支持关系/业务判断均为 null |
| README.md | 标签规则和填写说明 |

阅读材料将报告和资料按原文展示为缩进文本，避免其中 Markdown 标题与复核指南混淆。其中的指令都是待审数据，不应执行。阅读材料是便于查看的派生附件，正式导入仍以已绑定的 packet、原材料和填写表为准。

## 人工需要完成的工作

先看 reading.md，再在 review.json 填写：逐行是否含可核查事实、每个引用是否支持该行、每项业务标准是否满足，以及简短理由。通过的业务项必须引用正文连续原文，不能从来源文档借用引文。标明实际 reviewer 和带时区的 reviewed_at。

单纯标题不自动算事实；建议中的事实前提仍需检查。负向标准不额外要求固定免责声明，除非标准本身明确要求。资料不足不能推成产品绝不支持。不要参考模型旧分数来填表。

不允许把 Agent 填写的候选判断伪称独立人工审核。空表不代表通过，导出成功也不代表审核完成。导入后身份仍为 self-declared，程序不验证真实身份，不自动晋升策略，也不覆盖原模型结果或分数。

```powershell
.\.venv\Scripts\python.exe -m researchdesk.review import runs/technical-selection-pilots/7f88e78851ba4fe39cab347c1780d93a/execution/v2 --dataset evals/technical-selection-v1.json --bundle runs/reviews/technical-selection-v2-20261117 --review runs/reviews/technical-selection-v2-20261117/review.json --output runs/review-results/<新目录>
```

只有人实际填完后才运行导入。缺失标签、无时区时间、错误引文、缺少理由或材料漂移都应拒绝；失败时不写入已接受的人工结果。完整协议见 [人工复核](human-review.md)。

## 验证

本轮零 API。回归覆盖所选资料子集、完整资料的记录顺序、评分失败批次可复核、空白标签不被接受，以及缺失必需资料、未知资料、错误哈希和快照漂移拒绝。两份真实导出包均保留空 reviewer/时间和全部 null 标签。尚未产生任何真实人工复核结论。
