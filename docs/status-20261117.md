# 阶段交付记录：2026-11-17

ResearchDesk 的业务垂类是开发者技术研究与选型，工程重点是 Agent Harness 的可靠性、恢复、证据和评测。当前仍为 Phase 3：可交付的工程验证入口已经具备，研究质量尚未完成稳定验收。此记录替代 README 的当前状态入口，不覆盖 [2026-11-16 历史快照](status-20261116.md)。

## 阶段判断

| 阶段 | 当前依据 | 未完成的边界 |
| --- | --- | --- |
| Phase 1 主流程 | 已有真实网页研究、本地资料研究和引用报告；正常 CLI 全链路有脚本供应商测试 | 运行完成不代表所有结论正确 |
| Phase 2 可靠性 | 工具控制、持久化预算、回执、checkpoint 恢复、真实进程强杀实验 | 有限故障窗口；未知副作用不能盲目重试 |
| Phase 3 质量 | 语义验证、任务评测、诊断、候选策略实验、独立保存的复核材料 | 评分器有波动和合同失败；人工标签待填 |
| Phase 4 差异化 | 已做少量 Context 先导实验，默认策略未因此晋升 | 不宣称长任务优势；不强加 SubAgent |
| Phase 5 Skill | 方向有定义 | 尚未作为当前交付能力实现 |

框架提供 Agent runtime、checkpoint/context primitive、tool calling 等；个人贡献是应用层策略和验证，不能称为自研完整 Agent Framework。

## 质量实验的实际结论

| 实验 | 已有观察 | 工程决定 |
| --- | --- | --- |
| 3题报告写作对照 | 6份报告生成；写作 v1 评分失败，写作 v2 模型判定1/3通过 | [原结果](technical-selection-pilot-v1.md)保留；不判定候选更优 |
| 8个开发侧正反例 | 两版业务评分提示词均与8个候选标签一致 | [短例校准](task-grading-calibration.md)不能替代独立审核 |
| 4个长正文目标项 | 两版均与4个候选参考一致，但批次与标准数变了 | [针对性复核](task-grading-replay.md)不等于完全重放 |
| 完整原批次各重复2次 | 8次请求中7次输出有效；27项判定可比较且一致，9项未知 | [稳定性记录](task-grading-stability.md)无候选 v2 优势证据 |

所有候选参考仍是项目编写，不能称为独立人工 gold。原始资料和模型输出位于本地 runs，不随仓库公开；文档是结论与复现说明，不等于所有原始数据已公开可核验。

## 人工验收与交付入口

任务摘要已区分 scoring_status、model_gate、human_review 和 final_acceptance。评分合同通过不等于语义正确，模型门槛通过也不等于人工验收；见 [验收边界](model-assessment-boundary.md)。

两组技术选型报告各3份的 [复核包](technical-selection-human-review.md) 已导出：阅读材料、原证据、来源全文和空白表具备；reviewer、时间和全部标签未填。导入会另外保存人工声明及分歧，不覆盖旧分数，也不验证审阅者真实身份。Agent 不代填后宣称完成人工审核。

展示顺序建议：从 [快速开始](quickstart.md)运行零 API 演示，再读工作流/预算/故障边界，最后查看真实实验的失败与待复核项。日常查找使用 [文档导航](index.md)。

## 下一阶段的准入条件

先由实际审阅者检查摘记与 rubric、填写一批真实复核标签，再按已冻结条件检查评分器与人工分歧，保留失败和未知。只有获得质量依据后才决定是否扩展真实研究任务集或晋升候选策略。

独立标签未完成时，可继续解决具体可复现的实现缺陷；不靠重复同一组容易案例、扩大测试数或增加 Agent 数量来替代质量证据。本次阶段材料整理不改变任何生产默认策略，也不宣布 Phase 3 已完成。
