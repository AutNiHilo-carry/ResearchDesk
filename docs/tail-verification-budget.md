# 修订后的尾部验证预算

真实SQLite网页探测中，研究生成7次、原稿验证1次、修订生成2次耗尽共享10次额度，留下无法验证的候选。总额没有超限，但阶段策略没有为最后的验证保留空间。

本次基于既有请求准入和框架共享模型回调，增加应用侧持久化验证预留。没有提高上限，也没有把框架checkpoint表述为自研能力。

## 策略

原稿验证完成、未满足门槛时，只有剩余额度至少2次才启动新修订：至少一次生成，加一次候选验证。不足时跳过生成，保留原稿与缓存验证结果，selection.accepted=false、工作流needs_review。没有缓存原稿验证且额度已经耗尽的情况仍无法完成验收，这项策略不预留初次原稿验证。

开始修订时，在SQLite原子登记一个active验证预留。共享模型的每次generation或context_summarization准入都检查实际请求数加预留数，不能消费最后的验证额度。即使修订临时需要多轮模型或框架自动摘要，也要逐次通过这条门槛。

候选生成并通过引用结构检查后，repair_verification在同一事务内把预留标为consumed，并登记真正的模型请求reservation。之后失败、超时或进程终止仍占用请求，不能退款。预留本身不是SDK请求，不产生model_started事件或用量。

如果生成尝试使用最后一格而被拒绝，没有额外SDK调用。应用持久化预算回退意图，释放未花费预留，保留原稿并完成为needs_review；不会留着未验证候选当作最终报告。未完成的graph状态仍保留用于审计，但完成后恢复不再继续生成。候选引用结构无效时也释放未花费预留并回退。

已有候选文件可直接用最后一次额度做验证，不必再为不存在的生成阶段要求两格。旧的预算耗尽历史不会被自动提额或重写；原始SQLite失败样本仍保留。

## 持久化与故障

新增model_verification_holds附加表，保持现有数据库user_version和总额度策略版本。每个修订分支按路径摘要生成稳定hold ID；同一个active预留可跨进程复用，不叠加。数据库事务保证并发生成不能抢走验证格；同一库同时只允许一个active预留。

fallback意图先写入repair-state，再释放预留。即使在释放后、最终完成落盘前被中断，恢复也会读到回退意图，复用原稿验证，不重新生成。普通未完成错误保留active预留；未知的已发请求仍为已占额度。

诊断区分remaining（尚未发出的总格数）、verification_slots_held、generation_remaining，区分全额耗尽和尾部额度被保护。释放仅作用于未用预留，不能删除或退款真实reservation。

不保证远程exactly-once，不保证预留格能得到正确的模型响应，也不保证候选一定生成成功。这是一项避免“生成占完导致无钱验证”的保守策略，代价是可能放弃本可继续的多轮修订，并留下未花额度。无显式模型预算的历史运行沿用原行为。

## 验证

离线回归覆盖：余额不足跳过；恰好一轮生成加验证；多步生成被拦截并回退；已有候选最后一格验证；失败验证不退款；并发抢占；自动摘要角色；实际Deep Agents共享模型回调；强制终止后预留及未知reservation保留；回退意图落盘后中断恢复；完整工作流needs_review与完成恢复无新增调用。

测试模型和桩只证明策略、接线和恢复不变量，不证明报告质量改善。初次实现阶段未追加真实模型请求，不修改旧实验报告、候选或评分，也不将实验细分推断标签接入报告验收。
