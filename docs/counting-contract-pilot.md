# 计数合同下的两题真实写作对照

日期：2026-11-19。执行已冻结的 `version_scope` 和 `wal_default_claim` 两题，比较写作策略 v1/v2；两组均启用候选生成合同 body-length-v1。四份报告都完成并得到有效模型评分，但应用验收全部失败。精确计数提示没有保证正文合规，默认写作策略仍为v1、生成合同仍为legacy。

## 冻结范围

计划目录为 `runs/generation-contract-plans/5746f5fdbf8547d3abe02f453d26ffd4/`。执行前核对了全文资料、任务与 rubric、实际计数提示哈希、应用源码、模型和预算；没有漂移，execution 目录此前不存在。

固定 deepseek-flash、全文本地资料、同一计数合同和判分提示词，顺序 v1→v2；每题每组最多4次生成请求、每组最多两次批量评分，总上限20次 SDK 请求，无自动重试。引用评分采用 report-quote-v2，业务评分采用 research-task-rubric-v1；正文上限200码点，按[计数合同](body-constraints.md)忽略空白及规范证据编号，保留Markdown、标点等其他文本。

两组都收到同一计数提示，所以本实验比较的是该条件下的写作策略。它不是有提示与无提示的对照，不能估计计数提示相对legacy的收益。

## 保留的具体缺口

v1 版本题的总结和保留结论未带引用，模型将其判为事实，覆盖率仅0.5。v1 WAL题把读写并行与同主机/网络文件系统限制写在同一行，两条摘录各自只支持部分，被严格逐条整行支持口径判为partial；同时正文超长。

v2 两份正文都超过上限。版本题还输出“其余两条已记录证据”及 exact_quote_only 的尾注，增加了用户未要求的记录说明；这里保留原文，没有为提分事后删改。WAL题末尾建议包含无引用的读写并行事实前提，形成一条未覆盖事实。

事实性分类仍有分歧：版本题中，v1 的“不能确认17版所有锁行为与18版完全相同”被判为事实，而v2意义接近的保留结论被排除为未验证陈述。v2 WAL题的“资料没有固定SQLite版本，因此不能证明所有版本相同”也被排除为非事实。没有独立人工标签来判断这些排除是否恰当；因此不能把 v2 较高的引用指标全部归因于写作改进。逐行标签和所有排除项均已保留。

## 决定与局限

本轮展示了真实报告“模型通过但应用拒绝”的路径，不能证明生成计数提示改善遵循率。v2少一次生成、较少Token也只是本次观察，不构成稳定成本优势。两题是开发集，资料是项目编写的官方文档局部摘记；固定顺序、单轮、同一模型别名和未固定供应商后端快照都有局限。

不晋升写作策略或生成合同，不放宽0.9/0.6的引用门槛及200码点约束，不重写原标签，也不自动追加修订。human_review 与 final_acceptance 继续 pending。后续应优先核对长度失败的反馈路径和事实性分类分歧；如增加修订，须事先限制次数、保留完整业务要求并继续独立验证，不能在这两题上无限付费调提示词。
