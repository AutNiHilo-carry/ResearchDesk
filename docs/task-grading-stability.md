# 完整批次的有限重复评分

日期：2026-11-17。沿用 [长报告复核入口](task-grading-replay.md)，固定原技术选型试验的两个完整业务评分批次，检查评分输出与重复判定的稳定性。没有新增 Agent、生成报告或替换默认评分器。

## 冻结合同

两个原批次分别包含写作策略 v1/v2 生成的3份报告，每题保留全部3项 rubric、原问题、原资料顺序、task ID 和完整送评正文。正文按原提取逻辑排除 Evidence Ledger。输入由已核对代码重建，不是历史网络请求抓包；本轮保存输入和来源哈希。

每批分别使用评分提示词 v1/v2，各执行两次，总上限8次 SDK 请求，无 SDK 重试。第一遍提示词顺序为 v1→v2，第二遍 v2→v1；原批次顺序仍固定。既有入口允许显式配置2至3遍，本轮只执行2遍，不补跑失败请求。

评分请求只包含原问题、公开技术摘记、原报告正文和 rubric，不发送任何候选标签、路径或来源元数据。原批次没有负例；本轮保持输入不变，没有混入新负例，也不产生准确率结论。已有8例正反例校准是独立实验，见 [候选合同校准](task-grading-calibration.md)。

```powershell
.\.venv\Scripts\python.exe -m researchdesk.task_grading_replay runs/technical-selection-pilots/<原计划ID> --prepare-stability --repeats 2 --output runs/task-grading-stability/<新目录>
.\.venv\Scripts\python.exe -m researchdesk.task_grading_replay runs/task-grading-stability/<新目录> --execute-stability
```

准备阶段零 API；执行阶段只接受冻结目录，调用前校验输入、代码和提示词哈希。每次请求先记录调用位置，再进行派发。中断保留部分结果，执行目录只能创建一次，不自动恢复或重试。若在两次调用之间发生控制漂移，停止后续调用。

每条判定保存为 `batch/prompt/task_id/criterion_id` 对应的观察列表。只有两遍均通过严格输出校验才比较 true/false；批次校验失败导致的项保留 null，不计为一致或不一致。记录的是布尔判定稳定性，不比较引文/理由措辞是否相同，也不证明理由正确。

两遍、两个固定批次、全为正向结果，且模型为未固定后端快照的 deepseek-flash 别名，无法证明普遍稳定性或候选 v2 优势。温度0也未保证输出 schema 恒定。缓存命中与后端条件没有被控制，不作速度、成本或统计显著性比较。独立人工复核 pending，默认仍为 v1。

下一步优先收口评分使用边界：明确无效输出需人工复核，保留原判定，不用宽松解析或自动补跑换取通过。若继续调整提示词，需另建版本并在原失败输入及负例上验证；不为堆实验轮数无限重复调用。

离线测试覆盖完整输入保持、顺序交换、8次上限、真实 schema 失败形态、未知值保留、布尔翻转检测、计划漂移和中断后禁止重复执行。
