# Tool Policy 第一版

## 解决的问题
Agent 发起工具调用后，先经过应用侧 schema、权限、预算校验，再执行适配器。
Deep Agents 提供工具调度和中间件 primitive；ResearchDesk 定义调用策略、故障分类、
预算、同次运行缓存和执行审计。实现见 src/researchdesk/policy.py 和 tools.py。

## 默认限制

| 项目 | 默认值 |
|---|---|
| 应用工具调用 | 20 次，包括参数错误和缓存命中 |
| Tavily 请求 | 8 次，每个重试也占一次 |
| HTTP 超时 | 30 秒各网络阶段；连接最多 5 秒 |
| 只读请求额外重试 | 1 次，最多可配置 3 次 |
| 工具准入期限 | 从 runtime 创建起 180 秒 |
| 模型可见工具 | search_sources、read_source、record_evidence、write_todos |

write_todos 是框架的内存规划工具，不计入应用工具预算。
内置文件和 task 工具隐藏且执行时再次拒绝，不能绕过 Evidence Ledger。
模型输出 Token、费用和整个任务的墙钟时间尚无硬预算。

## 故障语义

- 严格参数类型、未知字段、空白、长度和 source_id 格式在执行前检查。
- 超时、连接故障、HTTP 408/429/500/502/503/504：只读工具可有限重试。
- HTTP 400/401/403/404、无效 JSON、结果结构错误、空结果和未知资料：不自动重试。
- 重试使用 0.25 秒起的指数退避；暂未解析 Retry-After。
- 所有网络尝试（包括失败和重试）都占请求预算；没有费用精确预算。
- 搜索结果整体校验通过才写入台账；提取结果 URL 必须匹配请求的资料 URL。
- 证据写入不自动重试。同一 claim/source/snippet 的稳定哈希维持重复写入去重。
- 成功的相同搜索/读取调用在本次运行内缓存，错误结果不缓存。
  缓存表示复用同一资料快照，不会刷新该 URL。
- 并发调用串行化，防止同一运行中的并发缓存穿透与预算超支。
- 超时依赖 httpx 的网络阶段超时；工具准入期限阻止新请求/重试，
  不能强制取消进行中的同步调用，也不是整个 Agent 的硬超时。

## 可检查的产物

runs/<run_id>/tool_events.jsonl 保存工具名、调用 ID、参数哈希、时间、预算使用、
完成/拒绝/失败/缓存命中、重试次数和错误码。不写参数原文、密钥、响应体或异常文本。
资料与证据原文仍存在专门的 ledger 中。
run.json 记录本次使用的 tool_policy 参数，便于复现实验。
audit 写入失败采用 fail closed，不继续派发新操作。

## 验证

使用 httpx.MockTransport 与可控时钟注入 503、401、超时、畸形结果和预算耗尽，
断言真实适配器调用次数、台账副作用和日志。
真实 Deep Agents graph 使用脚本模型验证 schema 错误和内置工具绕过会被拦截。
这些是工具层故障测试，尚不是进程 kill/restart 恢复测试，也不是研究任务质量评测。

## 范围和 trade-off

缓存和预算已持久化到应用 SQLite，配合操作 ID 回执支持重启恢复，仍不提供跨数据库 exactly-once。
重试只读搜索虽然不会重复写业务状态，仍可能产生重复 API 费用，因此逐次计费预算。
权限是静态名单，尚无用户身份授权系统；新工具必须显式注册 schema/适配器/只读属性。
JSONL 现在是 SQLite 中记录的导出副本，恢复时可重建。
恢复窗口和 kill process 验证详见 recovery-policy.md。
