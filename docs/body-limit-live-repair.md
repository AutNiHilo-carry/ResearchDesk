# 正文上限：一次真实修订与预算停止

日期：2026-11-19。对[计数合同两题对照](counting-contract-pilot.md)的两份 v2 原稿启用显式 `--body-limit 200`。版本题生成了合规短稿，但引用覆盖回退，被拒绝；WAL题因余额不足没有生成候选。两组都保留原稿，原稿仍超长，不能称为修订成功或应用验收通过。

## 事前冻结与费用上限

两份原稿、全文资料、已保存引用反馈、正文哈希、模型和已用预算事前冻结。复用原反馈前先做独立的冻结正文/缓存核验，并按修订模块的逐行绑定规则校验；没有重新付费评估原稿。继承原工具权限和运行额度，没有补额度或重置历史。

版本题的原额度为4、已用2、剩2，足够预留一次候选验证并进行一次生成；WAL题原额度4、已用3、剩1，不满足“生成+验证”要求，明确禁止该分支的供应商回调。

固定 deepseek-flash、原写作策略v2、正文上限200，显式启用 snapshot-v1 起始预算提示。该提示让模型看到仅剩一次生成；没有单独比较有无预算提示的收益。每份原稿最多一个修订图，无工具重试和自动追加轮次。

本次编排最多3次新 SDK 请求：版本题最多两次修订/验证；只有接受了不同的候选，才再进行一次独立业务 rubric 检查。WAL分支最多0次。原稿和修订分支的额度分别记录，不声称这些分支共享账户级全局额度；本实验另由一次性执行目录和事前总请求上限限制。

版本题触发 coverage_below_target、evidence_coverage_regression、fewer_supported_units。候选虽然缩短，但把原先带证据的“摘记版本范围为18、未核对17版”改成无引用陈述；结论也没有引用，被本次模型判为事实。保留的MVCC及冲突锁两条引用得到支持，因此精度为1，但整体覆盖率不足。不会因短稿达标就忽略这两条未覆盖事实。

原稿中意义接近的保留结论曾被判为非事实，新稿则判为事实；这处分类差异仍待人工复核。不过范围行的引用丢失和已覆盖事实减少同样存在，不能把拒绝全部归因于评分器分歧。原文、差异和新旧标签均保留，没有重新判分挑选较好结果。

WAL题因 insufficient_budget_for_repair_and_verification 在生成前停止，rounds_used=0，没有候选或候选评分。不是内容变短或新模型通过，而是正确保留了一次不足以安全修订的余额。

没有新报告被接受，因此按事前规则跳过独立业务检查，实际业务请求0。新短稿是否完整满足三条业务要求，本轮没有另做模型评估；不会拿旧稿的业务通过标签代替新稿验收。最终两个分支均 accepted=false、review_required=true。

## 工程结论

本轮证明真实运行中长度反馈可以触发原本会被“引用已通过”短路的修订，并且短稿仍被证据非回退门槛拦住；不足预算的另一分支在请求前停止。它没有证明修订质量改善，也没有让两份原稿达到应用验收。

这是同一开发任务上的单次修订，使用同一模型别名，无独立人工标签，提示词/模型后端也未作稳定性对照。不晋升默认策略，不放宽长度、引用覆盖或已支持行数门槛，不继续给同题补额度。human_review 和 final_acceptance 仍为 pending。下一步优先定位修订中丢失引用的过程及保留结论的事实性边界，继续保留失败证据。
