# 来源上下文与事实性提示：2×2首轮实验

2026-11-23，对两份原稿及一份被拒候选进行12次独立模型评分。**没有观察到可归因于候选因素的稳定收益，不晋升策略，不改历史评分和原修订选择。** 本轮仅评估保存正文，不生成新报告、不执行搜索或数据库操作，独立人工审核pending。

## 实验合同

新增`researchdesk.context_experiment`，在固定正文、引用、来源和deepseek-flash下，分别控制两个因素：来源完整正文上下文C、加强建议／混合句事实性规则的提示F。

| 组别 | C | F | 支持依据 |
| --- | --- | --- | --- |
| 00 | off | off | 原report-quote-v2，摘录独立支持 |
| 01 | off | on | 同一原payload，只追加事实性提示 |
| 10 | on | off | 原提示只追加来源上下文合同，payload包含同来源正文 |
| 11 | on | on | 来源上下文合同＋事实性提示 |

C因素包含输入正文和允许使用它的支持合同，是一个联合处理，不能进一步分离“更多资料”与“允许使用资料的措辞”。F按同一增量提示构造。C改变支持依据，不能把其分数混入原quote-only成绩。新实验的11提示由两个独立增量拼接，不冒充上一轮离线双输入导出中combined提示的原字节。

使用PostgreSQL原稿、Stripe API v1原稿、PostgreSQL被拒候选，固定此顺序，每份固定00→01→10→11，各一次，无自动重试、无加轮。候选正文先核对repair-state中的hash；生成任务标准不送给本轮引用评分器。

事前冻结计划中的正文hash、四组payload／prompt／hash、来源绑定、模型、SDK上限和全部src代码hash。执行前从源运行重建并逐项比较，漂移在加载凭证前拒绝；一次性execution目录阻止包括中断在内的重跑。每次调用前保存started，响应和用量另存；失败保留原响应，不剥离额外字段或接受无效标签，后续仅执行预先计划的其他组。

每份4次、最多3份，固定上限12次SDK请求；max_retries=0，temperature=0，timeout=90、max_tokens=8192沿用现有ModelJudge。不是账户／金额／总Token上限。输入包含原问题派生的报告行、引用摘录，C组另含公开资料中文摘记全文；发送到配置的DeepSeek接口。Tavily0，无报告生成请求。原生成额度和本独立评分实验分别记录，不重置原运行额度。

## 必须逐句解释的变化

- PostgreSQL原稿第一句仍被四组判partial；即使C组包含队列多消费者用途的完整资料，理由仍主要援引摘录不足。本轮不能证明模型已稳定执行扩展后的支持合同。
- Stripe的“保存以端点开始执行为界；未开始执行的情形资料未说明，证据不足。”在00组被判factual=true，在01／10／11组被判false。覆盖从3/6变为3/5，没有新增覆盖事实，也没有改正文。提示强调“任一事实前提”仍未稳定避免整句被免责声明排除，需人工复核。
- Stripe“不外推到API v2或跨服务端恰好一次”四组均判supported。00／01只有旧的截断摘录，其理由仍把“API v2、永久防重”视为整句支持；10／11则提及完整来源里的跨服务边界。因此本轮不能用同分证明摘录确实足够，也不能由C组分数高于历史成绩推导上下文收益。
- PostgreSQL候选第一句的版本限定曾在真实修订验证中判partial，本轮00原提示就判supported；四组都达到1.0。末行“建议：多worker领取任务可用此法……”四组仍判非事实。原始拒绝决定继续有效，不用事后较高分反向接纳候选。

这是开发侧阅读模型理由后的诊断，未填独立人工标签。固定顺序、每组单次、同一模型别名、事后选例和缺少独立参考限制了因果解释；temperature=0不等于结果必然一致。不会把本轮高分写成报告修订成功或研究质量提升。

## 复现与核查

准备一个JSON数组，每项含name、run（已完成运行目录）、body（selected或candidate）；candidate仅接受已绑定的revisions/candidate.md。最多3项，name唯一。仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m researchdesk.context_experiment prepare <samples.json> --output runs/context-factorial/<新计划>
# 上一条零API；下一条显式付费，每份4次请求
.\.venv\Scripts\python.exe -m researchdesk.context_experiment execute runs/context-factorial/<新计划>
```

prepare成功0，execute全部结构评分完整0，部分失败3，拒绝或操作错误1；0仅代表实验完成，不代表质量通过。没有resume、默认晋升或写回历史成绩。CLI仅execute在校验并建立一次性目录后加载当前目录.env；测试使用注入judge，不应称为真实模型结果。

真实计划和12组完整标签：`runs/context-factorial/20261123-a/`。零API审计：`runs/context-factorial-audits/20261123-a/audit.json`。禁止网络下核对计划未漂移、重复execute在加载凭证前拒绝，实验目录及3份源材料逐文件hash不变；12份用量相加等于25286。原始材料不提交公开仓库。

机制测试覆盖2×2的提示／payload因素构造、prompt／payload／预算／代码篡改在凭证前拒绝、原文漂移和未知候选拒绝、单次执行、失败响应保留且不重试、未知总Token保持null、禁止输出到原运行目录，以及上下文组的metric_scope显式区别于只看摘录。

当前保留默认quote-only-v2。后续优先建立独立审阅参考，明确哪些结论必须由摘录直接支持、哪些允许由同来源正文补足；先解决分母及合同遵循问题，再评估是否值得推广上下文输入。
