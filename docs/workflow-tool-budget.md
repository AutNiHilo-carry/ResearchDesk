# 受检工作流的工具预算

单次研究CLI已支持ToolLimits，但原工作流只保存模型预算，未提供工具策略参数，也未检查源/修订分支的工具策略是否与工作流计划一致。本次将已有工具策略参数接入编排层，不重写执行器或框架。

```powershell
.\.venv\Scripts\python.exe -m researchdesk.workflow "研究问题" --max-model-calls 10 --max-tool-calls 16 --max-provider-requests 4 --tool-retries 0
```

同样支持 --tool-timeout 和 --tool-deadline；默认值仍为现有ToolLimits。新工作流的plan.tool_policy记录完整策略，第一次研究时传入既有CLI，源运行及修订分支保留同一策略。恢复不允许传新预算；源、候选或计划参数与另一侧不一致时，停止并标记needs_inspection，不能静默扩额。

旧工作流没有该计划字段时保留历史校验行为，不补造已固定的工具预算。它们不能声称获得了新校验。计划和运行文件是本地版本绑定，不是防恶意管理员同时改文件的签名系统。

max-provider-requests计数包含搜索、正文提取及只读重试，修订沿用剩余额度；失败也占已经预留的请求。max-tool-calls单独限制应用工具调用。共享模型请求上限覆盖生成、框架摘要及工作流修订/验证，不是Token或费用上限。工具deadline仍为每个活动进程的准入窗口，不是整个工作流持久化墙钟上限；HTTP超时和进程恢复边界沿用原实现。

## 验证

离线回归覆盖自定义工具预算经实际CLI传入graph、源/修订fork保留、修改源或计划参数后的恢复阻断、恢复参数禁止覆盖以及旧计划兼容。脚本graph只证明接线，不证明真实研究质量。

真实网页验证将搜索、读取、证据与报告串起来，分别检查：是否实际执行外部请求，是否有正文快照、引用来自正文还是搜索摘要，预算是否守住，报告模型验证是否过门槛，以及完成后恢复是否重复请求。官方来源是任务要求；当前只约束工具类型和数量，尚未在应用层强制域名白名单，不能把Prompt要求描述成权限保证。

这类单次探测不是网页任务benchmark，搜索排名、网页内容和服务商响应可能变化；必须保留快照、原始报告、失败与模型评分，并明确人工审核仍待完成。
