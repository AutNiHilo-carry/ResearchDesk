# 业务评分器候选合同与校准

本模块针对技术选型首轮试验发现的两类风险：评分引文抄自资料而非正文，以及把“不要声称未经测量/全面优越”误解为必须出现固定免责声明。原始试验和分数见 [首轮记录](technical-selection-pilot-v1.md)，保持不变。

## 合同与边界

`task_grading.TaskJudge` 增加可选 `prompt_version='v2'`。v1 提示词字节保持不变，默认仍为 v1。候选 v2 明确区分：

- 引文只能取自请求中 `report` 字段的连续原文，不能从 `documents` 或正文外附件借用。语义相近可以用于判断，但不能改写 `report_quote`。
- 负向标准检查全文是否出现违例，不强制指定措辞；相关的有条件表述可作为判定见证，但单条引文本身不能证明全文没有违例。
- 正向标准要求报告确实写出内容；不能因为资料含有所需事实就判报告完成了要求。
- 若标准明确要求免责声明，缺失仍应失败；候选合同不豁免报告中的无依据断言。

严格 JSON、精确 ID、逐字引文验证继续复用 `grade_tasks`，不增加模糊匹配或自动替换。代码可以验证字节归属，无法单靠这一步保证语义判断正确。v2 目前只用于显式构造或校准入口，未替换任务评测、工作流或默认评分器。

## 八例校准

[任务文件](../evals/task-grading-calibration-v1.json) 包含有条件推荐/全面优越、未测量声明/编造测量、正文有单写者限制/仅资料有该限制、明确要求但缺失免责声明、正文语义改写八例。标签由项目编写，独立人工审核 pending；例子已用于开发，不是 held-out benchmark。

```powershell
.\.venv\Scripts\python.exe -m researchdesk.task_grading_calibration prepare evals/task-grading-calibration-v1.json --output runs/task-grading-calibrations/<新目录> --model deepseek-flash
.\.venv\Scripts\python.exe -m researchdesk.task_grading_calibration execute runs/task-grading-calibrations/<新目录>
```

`prepare` 零 API；冻结资料、报告、rubric、候选参考、模型、v1/v2 提示词与两份模块代码哈希。`execute` 最多2次 SDK 请求，v1→v2各批量判断一次，无 SDK 重试；候选参考和标签不放入请求。请求只包含自编短报告、题目、资料、criteria。

执行目录只创建一次；计划或代码漂移会拒绝调用，中断/失败保留结果，重跑被拒绝。第一组评分无效可继续第二组，但不会补跑第一组；比较中途控制漂移则停止。保留原始结构化输出、usage、失败信息和候选标签一致率，不生成或修订研究报告，不自动晋升。

## 回归验证

离线测试验证旧提示词哈希、正文/资料分离、语义改写时仍逐字引用正文、标签不入请求、SDK零重试、计划漂移、中断和单次执行。测试桩的标签一致率只说明比较接线可用，不是模型质量结果。

后续已对上轮实际长报告做 [针对性复核](task-grading-replay.md)：两版均与4个候选参考一致，但批次与验收项数量变化，尚未证明候选 v2 优于 v1。
