# 报告写作策略版本

## 问题与候选改进

2026-11-11 的本地虚构资料真实模型工作流中，原报告将“唯一可用来源”和“资料声明为虚构样例”写在同一条引用下。摘录只支持后者，不能证明输入范围唯一。原报告 Citation Precision / Evidence Coverage 均为 0.75；单轮修订增加引用逻辑解释后，覆盖率降至 0.50，精度仍为 0.75。工作流保留原报告并标记 needs_review，没有降低门槛。

`v2` 是针对该失败样本提出的候选写作策略：按问题组织正文，拆分不同证据范围的事实，将输入范围元信息与产品事实分开，建议中的事实前提仍须举证。修订直接改原句，不新增引用教学、同义改写或评分解释。用户要求的比较和限制必须保留，不能以删需求换分。

默认仍为 `v1`，原生成与修订基础提示词逐字保留。这里新增的是应用侧写作策略，不是自研 Agent runtime 或语义验证模型。

## 使用

```powershell
.\.venv\Scripts\researchdesk.exe "研究问题" --local-only --document ./notes.md --report-policy v2
.\.venv\Scripts\python.exe -m researchdesk.workflow "研究问题" --local-only --document ./notes.md --report-policy v2 --max-model-calls 12
```

恢复只使用保存的策略，不允许通过恢复参数替换版本。要比较策略应创建独立新运行，保留失败样本；不要反复修改同一份报告直到过线。

## 持久化与故障行为

新运行的 run.json 保存版本和两阶段追加指令哈希，SQLite 额外记录策略与实际生成/修订提示词哈希。修订分支继承这些绑定；恢复时版本、指令或实际提示词改变会拒绝继续。没有版本的历史运行保持旧行为，不补造提示词历史；发生模型调用后，不能再把旧运行重新标成新版本。

不修改证据结构、验证器、评分门槛或已有工作流最终结果结构。报告策略负责约束生成，Evidence Verification 仍独立判断引用支持；提示词约束本身不能证明正确性。

## 验证边界

离线回归覆盖旧提示词不变、实际 Agent 提示词绑定、本地工具范围、工作流参数与原始问题保留、修订继承以及恢复冲突在请求前拒绝。它们证明接线与恢复约束，不证明报告质量提升。

尚未进行 v2 的新增付费模型实验，人工审核仍待进行。后续应在冻结任务、资料、模型、预算与验证器后进行独立对照，并检查任务要求保留情况；单一失败样本上的改善不足以晋升默认版本。已有验证器一致性波动也需纳入解释。
