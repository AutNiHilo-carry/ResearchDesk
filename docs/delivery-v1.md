# 可验证的研究交付包

ResearchDesk 将已完整评分的任务批次整理为一个可携带的目录：报告、证据台账、保存质量明细、预算／用量声明和空白人工复核材料放在同一处。它复用现有Evidence Ledger、保存标签复算与应用门槛，不新增Agent Framework、不重做语义评分，也不自动授予研究正确性。

## 创建与验包

在项目根目录、已安装依赖的环境中执行，无需.env或API Key：

```powershell
.\.venv\Scripts\python.exe -m researchdesk.delivery create <原评测目录> --dataset <原任务集.json> --output <新的交付目录>
.\.venv\Scripts\python.exe -m researchdesk.delivery verify <交付目录>
```

create目前只接受status=complete且具有完整保存引用评分的批次。质量门槛失败的批次仍可导出供复核；scoring_failed、未完成评分、输入变化或不一致缓存会拒绝，不临时补跑评分。输出须为原评测目录之外的新目录，不覆盖旧包。

| 命令 | 退出码 | 解释 |
| --- | --- | --- |
| create | 0 | 交付包写成，原应用门槛通过；人工仍pending |
| create | 3 | 交付包写成，但原应用门槛failed或unknown |
| verify | 0 | 包内哈希、标签复算和跨文件关联通过；质量状态另列 |
| 任一命令 | 1 | 数据／绑定不合法、篡改、缺文件或操作失败 |
| 任一命令 | 2 | 参数错误 |

verify不需要原评测或原任务集，可以将目录复制到其他位置后执行。不要把“验包0”解释为“任务通过”，也不要只因create返回3就删除待复核交付物。

## 目录内容

| 文件 | 内容 |
| --- | --- |
| index.md | 阅读入口，逐题报告与模型／应用状态导航 |
| reports/001.md等 | 按任务顺序编号的原报告正文，不用task_id拼接路径 |
| evidence.json | 全部评分行、证据条目与来源快照，保留claim、snippet、位置和原有时间 |
| quality.json | 已保存的逐行引用标签与派生指标；不是新评分 |
| evaluation.json、assessment.json | 白名单评分分量、模型门槛和应用门槛，final_acceptance保持pending |
| statistics.json | 保存的生成计数、Token、耗时及声明的工具／模型额度；未知为null |
| provenance.json | 原结果和质量文件的字节／文本hash、规范化任务集hash、运行manifest绑定 |
| review/ | 标准逐报告复核packet、阅读材料和全空review.json，未代填人工意见 |
| manifest.json | 各文件SHA256清单，最后发布；缺少它的目录不是完整交付包 |

不导出.env、SQLite、checkpoint、事件原始日志、提供商响应或run.json任意扩展字段。报告、来源全文和机器评分理由是交付物的明确内容；本项目真实交付包仅放在本地runs，不随代码提交或上传CI。复核材料与机器分数分开放置，但整个包包含机器标签，不能称为独立盲测。

## 验证范围

创建时重建原问题、冻结语料、报告、Evidence输入及保存标签，验证业务rubric的报告原文锚点、正文约束和原应用门槛；观察到源文件变化即拒绝。写入前再核对来源，原批次不写回。完整评分输入与来源多文件读取不声称是对活跃写入者的原子快照，应使用已完成／停止写入的记录。

验包检查文件白名单、SHA256、包内路径边界、报告／分行锚点、台账／引用输入、已保存质量指标、业务标签、正文约束、两种门槛与人工空表。即使只改一份指标文件后重算文件清单，分量不一致仍会被拒绝。拒绝缺文件、额外文件、目录外链接或逃逸路径；最多256份文件、100MB总内容。

这是未签名目录的内部完整性与一致性检查，不认证作者、原站权威性、供应商后端或模型实际HTTP请求。能整体伪造一致材料的人仍可能改写清单；hash不是数字签名。验包不重新判断语义，不计算研究准确率、不自动晋升策略。

统计明确标为历史保存声明，不从事件重新测量，也不是新增消费。未知Token不填0，费用与Recovery Rate未测，不依据resume_count冒充故障恢复成功率。工具额度是原manifest的声明，不是给本包发放新额度。

## 人工意见与失败处理

先读review/reading.md，另存review/review.json到包外再填写，原包保持不可变。这里采用标准逐报告人工复核格式，导入协议见[人工审核](human-review.md)；与[稳定性事实性专用表](stability-review-guide.md)不同，不能互换。填写完整也不自动晋升策略，审核者身份仍为自报。

创建先在临时目录构建并验证内容，正式输出中最后发布manifest.json。写入中断可能留下附件或临时文件；保留失败目录排查，并用新输出目录重试，不手工发布临时清单。进程异常退出后先验包判断完整性，不靠退出码推断“肯定没有写成”；单文件原子替换不承诺整目录断电事务。

## 已做的真实记录检查

使用既有计数合同v2两题批次，禁用socket/DNS、dotenv及模型构建后，生成本地 `runs/deliveries/9183ac54abf941efa7462657d49be5c0/`：2份报告、13份被清单绑定的文件。create=3，verify=0；模型门槛passed、应用门槛failed、人工pending均保留，原评测全目录文件hash未变，新增API请求0。这是已有记录的交付验证，不是新的真实质量实验。

源码测试覆盖两种生成合同、可移植验包、失败／未知状态、未知用量、.env和私有响应字段排除、篡改后重算清单、来源漂移、输出保护及发布中断。CI还在非editable wheel、源码目录之外实际创建通过／待审包、验包并拒绝篡改；这些安装样例使用合成评分，不算人工参考标签。
