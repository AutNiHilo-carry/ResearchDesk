# 单轮证据绑定修订

初始报告可能有引用编号正确但摘录只支持半句话、推荐中的事实没有引用、把资料未提及的能力当作不存在等问题。此模块给生成流程增加一次验证反馈修订；不修改评测门槛，也不无限循环直到评分通过。

```powershell
.\.venv\Scripts\python.exe -m researchdesk.repair runs/<原RunID>
.\.venv\Scripts\python.exe -m researchdesk.repair --resume runs/repairs/<候选RunID>
```

原运行必须完成并有持久化应用状态。修订复制应用 SQLite 快照到独立候选目录，继承原工具权限、调用回执及已消耗预算，不清零预算。保留原报告、候选报告、差异、验证反馈和选择原因；原运行不被覆盖。框架检查点不复制；修订用独立的固定 thread，恢复依赖 LangGraph 提供的 checkpoint primitive。

修订输入只有原问题、原报告、证据和验证反馈，不含业务验收 rubric。最多执行一个修订图，工具仍可多次调用，但受原有剩余预算和图步数限制。验证请求另计用量。普通图执行的超时、步数限制不等于完整 token 预算。

候选先过引用结构检查，再由 line/v2 模型辅助验证。当前固定支持门槛为 Citation Precision ≥ 0.9、Evidence Coverage ≥ 0.6，且不低于原稿、不减少已支持行数、没有无效或冲突引用。拒绝没有可评分事实/引用的空泛报告，以及行验证器会跳过的代码围栏。失败保留原稿为最终报告，候选和拒绝原因仍可审阅。

这个支持门槛是保守的启发式规则，不能证明任务完整性；保留行数也不能证明保留了同一组事实。独立业务 rubric 评分与人工复核仍然必要。修订模型和评分模型相同，可能存在共同偏差。

恢复复用已保存的候选和验证结果。验证开始标记先落盘；若进程中断后无法确认远程验证是否完成，则拒绝自动付费重试。修订图按固定 thread 恢复，不启动第二轮；模型请求成功但图检查点未提交的窗口，仍可能重放模型调用，不承诺远程调用 exactly-once。运行完成后再恢复不会重做图或验证。

## 复用原稿的配对实验

```powershell
.\.venv\Scripts\python.exe -m researchdesk.paired_eval runs/task-evaluations/<基线评测ID>
```

实验先验证冻结任务、资料、原稿、证据输入、评分 prompt 和阈值的 hash，复用基线反馈，每份原稿最多修订一次。修订后按相同业务验收点和引用规则重新独立评分；不重新生成一个不同起点。可拒绝候选后沿用原稿，但最终是否成功由独立评分决定。

`result.json` 的生成 token 是原生成加本轮修订及内部验证的累计用量；`repair_added_tokens` 是每项新增用量，`newly_spent_tokens` 再加入本轮独立评分。每项累计耗时包含历史生成时间与本轮修订时间，批次耗时只测本次实验。未知用量保持 null，不换算为费用。

这三项虚构任务已经用于发现问题，属于开发集；不视为未见过的测试集。即使分数提高，也需要新任务、真实资料和人工标注进一步验证，不自动晋升默认生成策略。

## 后续真实预算回退记录

外部副作用题已复用原评分尝试一次定向修订。实际新增2次模型调用，随后为保留候选验证额度而停止；未生成候选评分，保留原稿，恢复无新增调用。见 [真实修订预算结果](targeted-repair-budget-result.md)。

## 可选预算提示

新修订可显式启用 --budget-context snapshot-v1，向模型提供起始生成/验证/工具额度快照，恢复仍复用原输入并由实时账本拦截。默认 off，尚未证明质量收益；见 [修订预算上下文](repair-budget-context.md)。

## 可选正文上限反馈

```powershell
.\.venv\Scripts\python.exe -m researchdesk.repair runs/<原RunID> --body-limit 200
.\.venv\Scripts\python.exe -m researchdesk.repair --resume runs/repairs/<候选RunID>
```

`--body-limit` 显式接受1到100000个码点，默认关闭，只接入直接修订入口。原稿即使通过引用门槛，只要没有满足该上限，也会进入至多一轮修订。反馈包含原始计数、失败原因和[统一计数合同](body-constraints.md)，仍要求保留业务要求、受支持事实和真实限制；不自动截断、删句或追加第二轮。

候选先保留原文、规范化记录和diff，再独立检查完整正文。仍超长或计数无效时以 candidate_body_constraint_failed 拒绝，不发起候选的付费语义验证；缺少 candidate-quality.json 表示本分支明确跳过验证，不能按0分或未知远程结果补跑。若长度通过，仍按原引用结构、0.9/0.6门槛、非回退和已支持行数规则验证，不能只凭短就选中候选。

原稿、候选和最终选择分别保存 original_body_constraints、candidate_body_constraints、selected_body_constraints；run.json 保存最终正文的 body_constraints。回退原稿也可能超长，此时产物仅为保留供复核的原稿，accepted=false / CLI返回3，不代表满足正文合同。status=completed 表示修订尝试结束，人工复核仍待完成。业务完整性仍须独立评价；长度加引用门槛不证明所有要求均已保留。

原模型/工具预算继续继承。即使有确定性长度检查，生成前仍保留一份验证额度：额度不足就停止，不为“先试着缩短”花掉最后一次请求。候选因长度被拒时释放未花费的验证预留。反馈可复用原已保存标签，避免重付原稿验证，但原反馈必须与正文逐行绑定。

上限与指令哈希同时绑定在修订状态、run.json 和候选 SQLite 的独立记录中；源数据库不改。修订输入只构造一次并保存 body_limit_input_sha256。恢复不能传 --body-limit 替换配置，文件缺失、未绑定输入、规则/指令变化或元数据降级都在模型请求前拒绝。完成后的恢复也重新核对原稿、候选、选中正文与计数回执，再返回已有结果，不重新发起模型调用。

这些绑定用于本地一致性，不是防篡改签名。明确新建 fork 可选择新的上限或关闭检查，不隐式继承父修订的上限；它仍继承已消耗预算，不是重新获得调用额度。旧修订默认行为和 REPAIR_PROMPT 保持原样；没有给历史修订补造计数记录，也未改变普通工作流或配对修订入口的默认策略。

开发阶段使用脚本供应商和故障桩验证分支、预算释放和恢复拒绝，零真实模型 API。后续[一次真实修订](body-limit-live-repair.md)把版本题从256缩到133，但因证据覆盖回退拒绝；另一题因额度不足停止。原[两题真实对照](counting-contract-pilot.md)的失败不改，不把长度达标等同修订成功。

定位被拒候选的编号变化与旧标签缺口，可用[只读修订引用诊断](repair-citation-diagnostics.md)。它保留改写未匹配状态，不自动补引用或重新调用模型。
