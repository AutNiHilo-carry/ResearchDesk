# 单轮证据绑定修订

初始报告可能有引用编号正确但摘录只支持半句话、推荐中的事实没有引用、把资料未提及的能力当作不存在等问题。此模块给生成流程增加一次验证反馈修订；不修改评测门槛，也不无限循环直到评分通过。

```powershell
.\.venv\Scripts\python.exe -m researchdesk.repair runs/<原RunID>
.\.venv\Scripts\python.exe -m researchdesk.repair --resume runs/repairs/<候选RunID>
```

原运行必须完成并有持久化应用状态。修订复制应用 SQLite 快照到独立候选目录，继承原工具权限、调用回执及已消耗预算，不清零预算。保留原报告、候选报告、差异、验证反馈和选择原因；原运行不被覆盖。框架检查点不复制；修订用独立的固定 thread，恢复依赖 LangGraph 提供的 checkpoint primitive。

修订输入只有原问题、原报告、证据和验证反馈，不含业务验收 rubric。最多执行一个修订图，工具仍可多次调用，但受原有剩余预算和图步数限制。验证请求另计用量。普通图执行的超时、步数限制不等于完整 token 预算。

候选先过引用结构检查，再由 line/v2 模型辅助验证。当前固定支持门槛为 Citation Precision ≥ 0.9、Evidence Coverage ≥ 0.6，且不低于原稿、不减少已支持行数、没有无效或冲突引用。拒绝没有可评分事实/引用的空泛报告，以及行验证器会跳过的代码围栏。失败保留原稿为最终报告，候选和拒绝原因仍可审阅。

这个支持门槛是保守的启发式规则，不能证明任务完整性；保留行数也不能证明保留了同一组事实。独立业务 rubric 评分与人工复核仍然必要。修订模型和评分模型相同，可能存在共同偏差。

恢复复用已保存的候选和验证结果。验证开始标记先落盘；若进程中断后无法确认远程验证是否完成，则拒绝自动付费重试。修订图按固定 thread 恢复，不启动第二轮；模型请求成功但图检查点未提交的窗口，仍可能重放模型调用，不承诺远程调用 exactly-once。运行完成后再恢复不会重做图或验证。

## 复用原稿的配对实验

```powershell
.\.venv\Scripts\python.exe -m researchdesk.paired_eval runs/task-evaluations/<基线评测ID>
```

实验先验证冻结任务、资料、原稿、证据输入、评分 prompt 和阈值的 hash，复用基线反馈，每份原稿最多修订一次。修订后按相同业务验收点和引用规则重新独立评分；不重新生成一个不同起点。可拒绝候选后沿用原稿，但最终是否成功由独立评分决定。

`result.json` 的生成 token 是原生成加本轮修订及内部验证的累计用量；`repair_added_tokens` 是每项新增用量，`newly_spent_tokens` 再加入本轮独立评分。每项累计耗时包含历史生成时间与本轮修订时间，批次耗时只测本次实验。未知用量保持 null，不换算为费用。

这三项虚构任务已经用于发现问题，属于开发集；不视为未见过的测试集。即使分数提高，也需要新任务、真实资料和人工标注进一步验证，不自动晋升默认生成策略。

## 可选预算提示

新修订可显式启用 --budget-context snapshot-v1，向模型提供起始生成/验证/工具额度快照，恢复仍复用原输入并由实时账本拦截。默认 off，尚未证明质量收益；见 [修订预算上下文](repair-budget-context.md)。
