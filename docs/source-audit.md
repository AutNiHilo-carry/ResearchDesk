# 引用来源审计

`python -m researchdesk.source_audit RUN_DIRECTORY --output NEW_FILE.json`

此命令离线只读运行数据库，按报告引用寻找证据，再将来源快照与成功保存的工具结果核对。它解决 `kind=web` 不能区分搜索摘要和提取正文的问题，不修改历史报告或评分，也不请求模型。

结果为 `search_snippet`、`extracted_body`、`both` 或 `unknown`。必须匹配快照完整内容、位置、内容哈希以及证据完整性。只有相同URL、标题或ID不足以确认来源。同一快照被两种工具返回时保留both，不擅自选择正文。缺失回执、预览回执没有完整内容、损坏证据均不作肯定判断。

来源记录和工具回执在同一个SQLite只读事务读取；正文位于数据库外，因此仅对已停止运行的目录审计。输出仅允许新JSON文件，避免覆盖历史产物。

这是应用内持久化记录的一致性检查，数据库不是防篡改的外部信任根。它不验证网页权威性、章节号、网页内容真伪，也不能证明模型没有采用其他材料。正文输出仍可能被截断（现有读取工具上限24,000字符），`extracted_body`不等于整篇网页全文。

验证器原有Prompt、缓存指纹、引用精度、覆盖率和门槛均保持不变。后续若把来源审计并入报告验证，应独立版本化并对照验证，不能把来源检查通过直接算作结论得到支持。
