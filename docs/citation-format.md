# 证据引用格式兼容

问题：模型可能返回 `［E…］` 全角方括号，即使 ID 完整且已记录，也会被原 ASCII 引用解析器遗漏。

应用层 `citation-brackets-v1` 仅将成对的 `［E…］` 转为 `[E…]`。不做 Unicode 全局归一化，不改正文、URL、ID、大小写，不补全缩写。混合括号、未闭合、嵌套和带空白的证据引用直接拒绝；最终保存仍要求每个引用都是账本中已存在的完整 `E` 加 16 位小写十六进制 ID。

每次报告保存或候选修订处理，先将精确输入保存为 `report-inputs/<sha256>.md`。格式合法时生成同名 JSON，记录规则版本、原文与规范化文本哈希、转换数量；这不是语义验证或通过标记。格式不合法的输入仍保留原文。已保存原文若遭改动会触发恢复错误。

通过结构检查后，`draft.md` 和报告正文采用标准引用。修订候选在计算输入哈希和请求评测之前转换；原始输出另外归档。已有评测开始记录或评测结果的候选若需要转换，拒绝恢复，避免修改已发送的评测输入。独立验证和分句解析也识别全角引用，但保持原文及位置锚点。

与扩大模型 Prompt 的替代方案相比，这一规则不增加模型调用且结果确定；代价是需要维护明确、有限的格式契约。它不能判断证据是否支持结论，也不能提高历史实验分数。
