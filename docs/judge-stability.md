# 评分一致性与三处争议诊断

本页是Agent辅助的工程诊断，不是独立人工标注，不填写或替代人工复核包。原报告、原分数、人工空模板保持不变。

## 已观察的问题

transfer实验的三份最终正文均未变化，引用评分完整输入相同；metric_denominator却从通过变为未通过。三处supported→partial分歧均出现在同一份Sable报告：

| 行 | 报告额外表述 | 所引证据 | 工程诊断与候选改写 |
|---|---|---|---|
| U6 | “重试计入分母，不另作独立计数” | 120次尝试已包含20次重试尝试 | 已包含是直接事实；“不另作独立计数”可能误解为不记录Retry Count。候选写成“120次总尝试已包含20次重试”，并明确该指标使用总尝试数，避免重复加20。 |
| U11 | “不可互相替代或换算” | 任务验收与工具尝试分别统计，工具成功不等于任务通过 | “换算”引入更强的绝对断言，摘录没有证明任何条件下都无法建立映射。partial有依据。候选只复述分别统计及不等同，不增加绝对结论。 |
| U14 | “单次虚构实验，样本与场景有限；所有结论不外推” | 数字只描述本次实验，不代表生产长期成功率 | 引用支持适用范围限制，但没有完整支持“虚构、样本与场景有限”这一整行。严格单摘录全支持口径下partial有依据。候选缩成证据直接支持的范围，或另引相应资料。 |

上述是待人工确认的分析，不把任何一轮模型判分设为真值，也不因为想提高通过率而放宽整行引用规则。算式110/120并不是这三处实际发生分歧的全部原因，不能把所有问题归咎于数学能力。相反，同一摘录有时被宽松接受、有时被严格检查，说明需要测量稳定性并复核参考标签。

## 固定输入重复实验

```powershell
.\.venv\Scripts\python.exe -m researchdesk.judge_stability <已完整评分的评测目录> --dataset evals/transfer-tasks-v1.json --repeats 3
```

重建并验证原评测完整引用评分payload的hash；不删减到三句，以免混入批次上下文改变。固定模型名称、line/v2 prompt、temperature、输出预算和同一资料、正文。每轮新建评分器，无工具权限，max_retries=0；默认3轮，只允许2至5轮。服务商模型别名可能更新，temperature=0不承诺输出确定。

在首次付费请求前保存input.json及控制信息；每轮调用前记录request_started，保留成功结果或未接受的输出、异常类型、用量与耗时。预定轮次是独立重复测量，不是错误后的追加重试；某轮失败仍占计划名额，不补轮。失败时不知道用量就记null。无自动resume，进程中断后不自动重新付费，已开始但未完成的轮次留在原产物中。

输出包含格式完成率、有效轮次两两事实分类一致率/引用标签一致率、每行每引用的标签分布和每任务各轮引用指标。只有至少两轮成功才计算一致性，格式失败不充当某一种语义标签，也不当作一致。全部通过的稳定性不等于正确性；两次都错也可以一致。小样本仅是本次输入的描述统计，没有估计总体置信区间。

不做多数表决，不挑分数最高一轮，不回写原评测，不计算新的Task Success Rate，也不自动更新prompt或策略。稳定性结果与独立人工标签是不同的产物。

## 回归覆盖与边界

离线测试覆盖精确的两两一致率、原始输入一致性、prompt变更阻断、标签输出缺项、未知用量、重复预算、输入突变和历史产物保护。测试桩不是评分正确性或人工审核的证据。

下一步仍是由人工对争议表述及候选改写进行复核；如要修改评分合同或prompt，应先形成明确规则，再用独立参考标签和更多新样本做对照，不在这三行上反复调到全对。

## 已保存生成合同的批次

稳定性入口已与配对修订的 legacy 生成默认值解耦，支持完整已评分的 legacy／body-length-v1 批次。它先用人工复核包的资料绑定和保存评分确定性复算检查报告、来源、引用标签与指标，再根据每题保存的生成合同检查实际后缀、原问题哈希及运行元数据；不允许替换合同或补预算。尚未完成生成的任务、未知合同、变化的原问题、语料或缓存会在加载凭证／构建模型前拒绝。

仅引用评分参与本次重复，因此不再强制业务评分器使用默认 v1 Prompt；实际引用评分必须仍是已支持的 report-quote-v2，且结果元数据、保存评分和当前提示词哈希一致。该入口不修改配对修订的校验条件，不调用业务评分器，也不发放新的任务通过结果。

例如此前通过 Python API 复放的 body-length-v1 原批次，现在可通过正式命令复放（该命令最多调用模型2次，会产生费用；本次代码修复没有执行新的付费复放）：

```powershell
python -m researchdesk.judge_stability runs/generation-contract-plans/5746f5fdbf8547d3abe02f453d26ffd4/execution/v1 --dataset evals/technical-selection-v1.json --repeats 2 --output runs/judge-stability
```

控制记录新增生成合同、后缀哈希与历史评分文件哈希；旧合同记录缺失时只接受能按 legacy 后缀核对的历史批次，不伪造一份生成合同。重复评分次数与默认行为不变，没有自动恢复、补轮或覆盖旧结果。

## 保存结果的零 API 核验

已有正式稳定性结果可以直接核验，不必先手工复制成第二份评测目录：

```powershell
python -m researchdesk.judge_stability runs/generation-contract-plans/5746f5fdbf8547d3abe02f453d26ffd4/execution/v2 --dataset evals/technical-selection-v1.json --check-result runs/v2-formal-stability/13d4b90822d54de3ac288c2570726cea/executions/1e150d37df2a429a98a96b54e40417aa/result.json --output runs/stability-checks
```

此路径在加载 dotenv 或构建 ModelJudge 前返回，不需要 API Key，不调用模型，也不恢复或补跑轮次。不能同时提供 --repeats 替换已记录的次数；新付费评分入口仍默认3轮，原有行为保留。

检查会重新核对原评测与历史缓存、控制条件、完整输入对象、逐轮身份及Prompt；对完成轮次确定性复算保存标签、指标和任务引用统计，再复算已有汇总。控制字段缺失或变化、错误文字／指标、重复轮次、伪造完成状态和观察到的文件漂移都拒绝。严格检查面向具备当前正式CLI完整绑定字段的结果，旧自定义API产物不因缺字段就被推断为可信结果。

每个完成轮次另与冻结历史标签比较事实分类。新轮次彼此一致并不足以通过：相对历史发生事实分类变化，状态为 review_required；评分中断或存在未完成轮次，状态为 unknown。两者退出码均为3。只有预定轮次全部完成、保存记录核验通过且事实分类均与历史相同才返回0。非法记录返回1，参数错误返回2；失败和未知不会按0分或100%一致处理。

输出到新的 audit.json、gate.json 与 summary.md；gate.json 采用 stability-factuality-gate-v1，并以 audit_content_sha256 绑定规范化审计内容。输出不能落在原评测或原稳定性目录内，任何原报告、缓存或标签都不写回。source_recorded_tokens 是旧结果记录的用量，不是检查新增消费，未知用量保持null。

该门槛仅证明本次保存记录的事实分类一致性，不认证真实HTTP请求、作者或模型后端快照，也不证明引用正确、报告质量、任务通过或人工审核完成；human_review 与 final_acceptance 始终pending，不自动晋升策略。

### 从门槛结果到人工复核

有效保存记录核验后另附 `review.md`、`review-context.json` 和 `review-template.json`，无需再从机器审计文件手工摘句。阅读文件包含原问题、完整评分输入的所有行与引用摘录；不是只挑分类变化行。它保留评分入口的分行正文，摘录不是完整原文，不能把上下文缺失视为反证。

上下文不附机器事实性标签、评分理由或推荐答案，机器差异仍在 `audit.json`；阅读表述中的原始文字不会按关键词删改。上下文通过规范化哈希绑定审计和完整评分输入，空表再绑定上下文。哈希仅用于绑定这些对象，不认证审核者或保证未来文件不被修改。

空表逐行提供 factual=null、atomic_claims=[]、reason=""，审核者和时间留空。先阅读全体材料，再另存填写意见；无法判断时保留null并说明资料缺口，不能把未知强填为false。表格没有自动导入或策略晋升流程，**不能传给 `researchdesk.review import`**。独立人工意见未收到前，门槛、历史成绩和人工pending状态均不变化。

这些材料是在观察模型分歧后生成的事后复核输入，即使未展示机器标签，也不能称为独立盲测、人工参考答案或新的准确率实验。安装包验收同时核对全量输入、上下文哈希和人工字段留空；合法的中断记录也生成材料，损坏记录仍直接拒绝，不生成复核包。

已用真实v2保存记录在禁用网络、凭证加载与模型构建的进程中生成材料：本地 `runs/stability-direct-checks/6e711131be6747aa917c57552e6876f7/85855f2d2d5545dd92228f15297cbc26/` 包含2题共17行，人工字段全部留空；门槛仍为review_required／3。源评测与稳定性目录逐文件哈希不变，新增API请求0。这份新材料不替代此前8组候选近义句复核包，两者范围与格式不同。

### 专用人工意见记录入口

填写后的稳定性复核表使用专用命令，仍不能交给常规逐报告的 `researchdesk.review import`：

```powershell
python -m researchdesk.stability_review <原评测目录> --dataset <原任务集.json> --source <稳定性结果/result.json> --bundle <包含review-context.json的目录> --review <另存的填写表.json> --output <新的意见记录目录>
```

保留version、context_sha256与每行unit_id，填写reviewer及含时区的reviewed_at。每行factual只能为true、false或null；有确定标签时必须写reason。atomic_claims用于拆分表述，列表中的字符串不能只含空白。无法判断可保留null并说明原因，不能用false代替未知。所有评分行都必须出现一次，未审核行保留空值，不能删掉；status可以保留模板的pending，由程序计算实际完成度，若手填partial／complete则必须与实际一致。

该命令重新运行零API保存结果核验，从原评测、稳定性记录和任务集重建当前复核包，再核对审计、门槛、完整上下文、空模板与阅读文件。即使同时修改上下文和填写表里的哈希，也不能绕过原记录校验。写出前再次检查实际使用的来源、复核包和提交文件，观察到变化即拒绝；这些多文件检查不是对活跃写入目录的原子快照，应使用已完成／停止写入的记录。

合法意见另存submitted-review.json、result.json和summary.md，不覆盖既有输出或任何原记录。全部行都有确定标签时返回0／complete；存在null时返回3／partial，保留未知数与原意见；身份空白、时间无时区、字段类型错误、缺行、重复行、来源变化或绑定不符返回1，不写接受结果。返回0仅表示意见格式与绑定完整，不表示意见正确或研究通过。空白模板没有审核者和时间，不能当成已完成意见导入。

审核者身份为自报、未经认证；此入口记录事实性意见，不计算准确率，不比较模型优劣，不评判引用支持关系，也不授予Task Success或修改原门槛。accuracy保持null，final_acceptance保持pending，promotion保持none。本轮仅用明确标注的合成测试意见验证命令，没有填写或导入真实人工标签。

wheel安装验收另覆盖四种合成提交：完整记录返回0，部分未知返回3，空白模板和错误上下文绑定均返回1；子进程禁用网络、dotenv及模型构建，原复核包保持不变。

### 安装包中的保存结果检查

`scripts/smoke_wheel.py` 将此入口纳入非 editable wheel 验收：安装后在源码目录之外，通过独立进程执行四类固定记录。历史分类一致返回0／passed；两轮新分类相互一致但偏离历史返回3／review_required；仅保存一轮的中断记录返回3／unknown；重复轮次身份的损坏记录返回1，且不生成门槛文件。

子进程禁用socket连接、DNS、dotenv加载及ModelJudge构建，并清除模型／搜索Key环境变量。验收核对审计哈希、人工验收pending、无策略晋升，以及原评测、资料和逐轮记录未变化。结果写入wheel验收产物的 `factuality_gates.saved_stability`，摘要逐项列出退出码；CI会保存安装包检查产物。

这些记录由固定回调离线构造，测试退出边界和安装行为，不是真实模型实验、人工参考标签或研究质量证据；审计钩子也不等同于通用操作系统网络沙箱。
