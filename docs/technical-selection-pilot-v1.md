## 失败定位

v1 的 `wal_single_writer/single_writer` 返回引文“同一数据库同一时刻只有一个写者”。该文本存在于附带资料/证据，但不是实际送评报告正文的连续子串，因此严格校验拒绝整个批量业务评分。不能通过从证据附件找同一句话来接受它，也不能将未知任务通过率补为0或1。本地另存 `execution/quote-diagnostics.json` 记录离线逐字核对。

v2 的 `local_low_write` 报告确有“资料未提供……测量数据，因此不能断言 SQLite 在该场景优于服务器数据库”的限制说明，但业务评分仍将 bounded 判为 false。该项存在明显复核需要：候选 rubric 要求不声称未经测量/全面优越，评分器却可能额外要求某种明确措辞。本轮保留原判定，不事后改标签或重算成通过。

v2 的 `wal_single_writer` 将架构建议与单写者事实放在同一句，并附单写者证据。引用评分判为 partial，理由是证据没有支持改用其他数据库的建议。这里涉及建议与事实混合行的评分范围，应结合已有 scope/inference 机制复核，不能直接归因于数据库知识错误，也不能放宽门槛消除失败。
