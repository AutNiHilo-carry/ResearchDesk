# scope / inference 候选合同 v2

v1 的8例真实校准中，2处差异都在 scope：文档缺失→产品能力否定，以及研究任务分母→工具尝试分母。两次最终支持/不支持结论仍一致，不能将细分字段差异直接等同于模型错误。旧参考和原输出均保留，本轮提出明确的新合同，默认仍使用 v1。

## 维度职责

| 维度 | 检查对象 | 候选 v2 规则 |
|---|---|---|
| premise support | 声明前提与证据 | 证据是否支持前提本身，不能用结论合理性代替前提举证 |
| scope | 前提被用于结论时的显式适用范围 | 主体、产品、版本、套餐、运行条件、群体和计量单位；明确不匹配=inconsistent，必要范围未知=uncertain |
| inference | 从前提到结论的有效性 | 是否加入未证实前提、跨越文档信息与产品事实、或进行了无效推导 |
| strength | 结论的确定程度与覆盖范围 | 是否把未知说成绝对否定、把有限证据推广为普遍保证 |

维度不互斥。把任务分母用作工具分母，既是计量单位不匹配，也使推断无效；可同时失败。资料没有提及某能力，若主体和版本没有变化，这一缺失本身不算显式范围不匹配；从缺失推出“同一产品绝无此能力”主要是无效推断与过强结论。

有意且归属正确的跨版本比较不应仅因版本不同而判范围不一致。相同日期不能证明同版本，但完整资料已经明确写了版本时，理由也不能假称版本只来自日期推断。理由中的未解决假设应反映到相关字段，不应文字保留而字段全正向。

以上是项目自拟的候选定义，尚待独立复核。它没有自动证明理由真实性，也不保证模型遵循。后续可能仍有歧义，须记录分歧，不能把合同文本当作准确率结果。

## opt-in 与兼容性

原 inference-check-v1 PROMPT 逐字保留。v2 在末尾追加合同，输出字段、锚点校验和最终支持派生规则不变。ModelJudge 默认仍为v1，现有单句 CLI 也继续使用v1；只有校准包显式选择v2，批量执行才发送v2提示词。

```powershell
.\.venv\Scripts\python.exe -m researchdesk.inference_calibration prepare evals/inference-contract-v2-cases.json --judge-prompt v2 --output runs/inference-calibrations/<新目录>
```

本命令离线，不读凭证、不调用模型。校准包保存版本与有效提示词哈希，单次执行计划继承绑定，校准结果也记录版本。复用校准包或执行计划时，版本/提示词不匹配会拒绝。批量执行不支持自动恢复重试。逻辑变化后不迁移或重写旧包，另建新包；历史已完成实验文件保持原样。

## 新案例与验证边界

新增8个开发案例，覆盖：显式同版本、同日不同版本、合法跨版本比较、套餐网络条件不匹配、有限资料下的保留结论、同产品绝对否定、正确计量单位和分母混用。候选参考采用v2定义，未改旧8例参考。案例在观察旧分歧后编写，因此不是独立 held-out benchmark；更换产品和数字也不能消除设计偏差。

离线回归只验证原提示词冻结、默认v1、v2从校准包到模型适配器的实际传递、版本替换拒绝，以及两版对同一结构化输出仍采用相同派生规则。测试桩和候选标签不是语义准确率证明，本轮没有新增付费实验。

后续比较应在同一新案例、固定模型和设置下并列运行v1/v2，并标明两组都相对于v2候选合同评分；不能拿旧案例上的旧合同指标直接当作对照。需复核参考标签与模型理由，保留全部失败，不自动晋升默认版本或接入研究报告验收。
