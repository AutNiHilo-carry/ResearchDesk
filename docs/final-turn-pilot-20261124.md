## 最后阶段的定向回放

为观察开关实际触发后的行为，从上面的关闭组取出已通过发布检查的 189 字符草稿、公开资料和引用摘录，复算它与最后一次预检的一致性。开启组和关闭组均从这份固定材料开始，各有一次新的模型调用额度。实验只检查能否发布正文，未发起语义评分或 Tavily 请求。

首次输入将草稿与预检反馈拼成一对历史工具消息。脚本模型的演练通过，但 DeepSeek 两组各返回一次 `OpenAIInvalidRequestError`，用量未知，没有候选正文或交付。开启组的应用日志有一次 `final_model_turn` 事件，表明应用执行了最后一轮控制。该事件发生在模型请求前，交付结果仍为失败。

该构造与接口限制冲突。DeepSeek 的 Chat Completions 文档说明客户端插入工具调用历史需使用支持该形式的接口。失败回执仅保存异常类型，无法从回执确认服务商的具体拒绝理由。[DeepSeek 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/#inserting-tool-calls-mid-conversation)

修正版将原问题、草稿和预检结果作为同一条普通用户消息中的数据。通过真实 SDK 的模拟 HTTP 传输检查序列化结果，两组各产生一条模拟请求，用户消息相同，只有关闭组的请求包含可用工具。模拟返回原草稿时，两组均通过实际应用发布流程。服务商对新请求的接受情况及模型交付结果仍待验证。

两个计划都保存在 `runs/final-turn-draft-replay/` 下，`20261124-a` 留存原失败，`20261124-b` 仅冻结修正输入。离线审计确认原计划拒绝重复执行，且所有文件哈希保持一致。本次实际发出两次 SDK 请求，返回 Token 未知，已到本次预设请求上限。
