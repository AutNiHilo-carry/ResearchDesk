# 草稿检查迁移对照：两组各交付一题

2026-11-24，在两组均启用最终正文门槛的条件下，对 SQLite 在线备份和 PostgreSQL 队列领取做了一次草稿检查 off/on 对照。两组应用通过率均为 1/2，通过的是不同题目。开启组多用 3 次生成请求和 11,403 Token，草稿检查继续作为显式选项。

两题此前已用于项目开发，这是它们首次参与草稿检查对照。上轮快照和外键题的开启组通过 2/2，关闭组通过 0/2。此次更换了任务，并在两组同时启用发布门槛。每组固定顺序执行一次，人工验收仍待提交。

## 实验条件

先执行 off，再执行 on。每组依次运行 `sqlite_live_backup` 和 `postgres_queue_claim`。两组共同使用 `deepseek-flash`、写作 v2、full 上下文、任务集自带公开摘记、`body-length-v1` 和 `--final-body-limit 200`。每题最多 5 次模型请求、10 次工具调用，任务超时 240 秒，外部搜索额度和工具重试均为 0。业务评分 v1 和引用评分 `report-quote-v2` 沿用原标准，引用精度门槛 0.9、覆盖率门槛 0.6。

开启组增加 `--draft-inspection-limit 200`，因此该因素同时包含工具及配套提示。实验启动前冻结任务、语料、策略、评分提示、脚本和代码哈希。最多 20 次生成请求加 4 次批量评分请求，实际请求与返回用量分别统计。运行目录一次性创建，已有执行在加载凭证前拒绝。模型处理项目公开资料摘记、研究问题、正文及评分材料。Tavily 请求 0，预算剩余 5 次。

- PostgreSQL 关闭组的引用结构检查通过，长度超出 3 个计数码点。原样保留候选和拒绝回执，业务和引用批次均跳过该题。这是 `publication_rejected` 在真实模型运行中的观测。
- SQLite 开启组调用一次草稿检查，回执记录 161 个计数码点。5 次生成请求用完后，运行在尝试继续时被预算拦住。任务评测记为 `generation_failed`，运行清单保留具体原因 `budget_exhausted`。该组没有最终正文或发布回执。
- PostgreSQL 开启组有一次成功预检，最终正文比被检查稿多 10 个计数码点。最终发布门槛对实际正文独立检查，回执标明 `matches_last_preflight=false`。

两份成功交付均获业务与引用评分通过，两组批次各执行一次业务评分和一次引用评分。应用通过率以全部两项任务为分母。对照中有一项改善、一项退化，且关闭组被拦的 PostgreSQL 候选没有引用分数，因此不能用通过组的分数估计开关带来的引用分差。
