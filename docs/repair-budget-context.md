# 候选修订预算快照 snapshot-v1

针对 [真实修订预算回退](targeted-repair-budget-result.md)，新增显式启用的修订起始预算提示。上轮虽然账本会硬拦截，模型却没有在修订消息中看到可用生成回合和工具余额，连续使用工具后无法再完成报告。

本能力只改变修订输入，不增加额度、工具权限或修订轮数；支持门槛、验证尾部保护、候选拒绝和完成态复用继续由原代码执行。默认 off，尚无真实模型质量改善证据。

## 使用

```powershell
.\.venv\Scripts\python.exe -m researchdesk.repair <源Run目录> --destination <新的候选目录> --feedback <已绑定反馈.json> --budget-context snapshot-v1
.\.venv\Scripts\python.exe -m researchdesk.repair --resume <同一候选目录>
```

第一条会执行真实模型请求。功能实现轮次仅离线验证，后续已完成 [固定条件真实对照](repair-budget-comparison.md)，未得到可接受的新修订结果。feedback 仍使用原机制，不向修订模型传入业务 rubric。省略选项或指定 off 保持旧输入行为；resume 只用保存的策略，不接受替换预算上下文选项。

已有原稿达到支持门槛时仍直接复用；本选项不会为了修订而改变门槛。只有真正进入生成阶段时，才在申请验证预留后生成快照。

## 模型可见的信息

账本事务读取起始快照，字段采用白名单：

- model：上限、已 admission 的调用数、总剩余、验证预留数，以及扣除预留后的 generation_remaining。
- tools：调用上限、已用与剩余，以及外部请求上限、已用与剩余。

generation_remaining 为2意味着工具调用之后通常还要再用一个生成回合输出报告，不能把它理解成可以任意执行两批工具后再额外生成。附加提示要求预留一个生成回合完成报告，优先复用已有证据与 ID；仅剩一个生成回合时优先输出有据的完整稿件。

旧运行没有模型调用账本时，model 为 null，不能当成无限额度或0额度。工具/外部请求余额为0时保留0。这里没有新增 Token、金额或总时限预算，也不保证模型遵守提示；实际 admission 和权限检查仍是唯一硬约束。

## 冻结与恢复

候选策略版本和提示词哈希同时写入修订 state 与候选 manifest。repair-input.json 包含原始消息、反馈、证据与预算快照，整体哈希保存后才开始生成。

恢复不刷新快照，也不将已用额度改回快照中的数值。图可能已进行若干回合，因此保存的数字会过时；实际剩余仍以持久化账本为准。复用原输入是为了避免恢复时悄悄改变已检查点化的消息。

未知版本、提示词漂移、两份策略记录不一致、输入变化/丢失、部分准备只有输入却没有绑定哈希，以及去掉策略但残留哈希，都在后续模型调用前拒绝。输入写入与哈希状态提交不是跨文件事务，间隙中断时保守要求检查，不自动重建。哈希不是外部签名，不能防止有权限者一致地修改全部记录。

旧运行没有新增字段时按 off 处理；不会追补预算提示或改写旧消息。已完成的旧回退分支仍直接返回原决定，不因还有剩余额度而重开生成。

## 验证与边界

本轮零真实 API，完成以下检查：

1. 快照明确扣除候选验证预留；缓存原稿反馈时不新增原稿评分调用。复现“总额度6、已用3、为验证留1、可生成2”的条件。
2. 实际 Deep Agents graph 中的脚本模型收到快照，生成与验证仍共用原硬额度。
3. 中断后再次生成使用原快照，即使账本可用生成回合已减少；没有刷新输入或恢复额度。
4. 输入/策略漂移、隐式降级、部分准备和 CLI 恢复覆盖参数都被拒绝。
5. 上轮真实完成回退目录经新代码读取，原文件和运行计数均不变，评分器和生成器均未被调用。

测试标签只验证工程接线，不证明修订质量提高。下一步如需评估收益，应对相同原稿、反馈和已用额度分别冻结 off 与 snapshot-v1 的新分支，保留上轮失败；不能覆盖旧分支、补预算到成功或凭一次改善自动更改默认行为。
